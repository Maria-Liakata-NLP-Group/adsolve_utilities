# Therapeutic Sessions Bundle Data Prep — Design

## Problem

The therapeutic_sessions dataset (`/Users/sebastian/Affiniti/ml-automation-core/datasets/therapeutic_sessions/`)
holds 27 patients (`<user_id>/` folders) and 149 sessions. Each session has two files:

- `<user_id>_<session_id>.json` — the conversation transcript: `{user_id, session_id, session_type,
  content: [{role, content}, ...]}`.
- `<user_id>_<session_id>_session_summary.json` — `{problem, activity, outcome}`, all three fields
  always non-empty.

There's also a `<user_id>_patient_summary.json` per patient (cross-session), not used here.

The evaluation bundle being generated by `generate_bundle.py` (see
`2026-07-22-metric-bundle-generator-design.md`) will run `intra_nli`, `mhic`, and `fc` (as
`fc_document`) over a use case. Per the metric registry: `intra_nli` needs only the LLM summary
text; `mhic` and `fc_document` both need the summary plus `posts` — a list of reference strings
bound via `reference: posts`, loaded from a `document_id -> [str]` JSON. None of the three bind to
`gold`. The dataset needs converting into that shape before the bundle can run on it.

## Data mapping

For each paired session:

- `document_id` = `f"{user_id}_{session_id}"`.
- `llm_summary` = `f"{problem} {activity} {outcome}"` (space-joined; all three fields already end
  in terminal punctuation in the source data).
- `posts` = each turn's `content` string from the conversation's `content` list, in order, **excluding**
  any turn whose stripped content starts with one of these lead-in phrases (case-insensitive):
  - `"system prompt"`
  - `"a patient has selected"`
  - `"a therapist asked a patient"`
  - `"from this point, imagine that the ai is"`

  These four phrases were identified by scanning every first-assistant-turn in the full dataset
  for length outliers, then inspecting the outliers: they are instruction/system-prompt text that
  leaked into the transcript as a turn, not genuine dialogue. Confirmed via full scan: 6/149
  sessions match, always at turn index 0 today. The filter matches on content, not position, so it
  keeps working if that ever changes. Turn length is NOT used as a filtering signal — genuine
  assistant messages range up to ~460 characters and overlap with the leaked-instruction range, so
  a length threshold produces both false positives and false negatives (verified empirically).

## Output shape

Two JSON files per run:

- `llm_summaries.json` — `{document_id: str}`
- `posts.json` — `{document_id: [str, ...]}`

No `gold_summaries.json` is produced — not needed by `intra_nli`/`mhic`/`fc_document`.

## Script

`evaluation_bundles/prepare_therapeutic_sessions.py`, CLI:

- `--input_dir` (default `/Users/sebastian/Affiniti/ml-automation-core/datasets/therapeutic_sessions`)
- `--output_dir` (default `evaluation_bundles/data/therapeutic_sessions`)
- `--limit N` (optional) — if set, randomly sample N sessions from the full paired set before
  writing, using `--seed` (default `42`) for reproducibility. Used to produce a small test set,
  e.g. `--limit 5 --output_dir evaluation_bundles/data/therapeutic_sessions_sample/`, run once and
  checked in for repeated manual testing.
- No `--gold_summaries` output and no such flag, per the data contract above.

**Pairing and error handling:** walk `<input_dir>/<user_id>/` for every user folder; for each
`*_session_summary.json`, look for the sibling conversation file (same prefix, without the
`_session_summary` suffix). If either file is missing/unreadable, or a summary field is empty
after stripping, skip that session and print a warning naming the file — do not crash the whole
run over one bad session. Every session in the current dataset is expected to pass (149/149
verified during design), so warnings are a signal something changed in the dataset, not expected
steady-state output.

## Testing

Unit test in `evaluation_bundles/tests/test_prepare_therapeutic_sessions.py`, following the
fixture style already used in `test_generate_bundle.py`: a small in-repo fixture directory with
2-3 fabricated user/session folders, one of which includes an instruction-leak turn matching one
of the four lead-in phrases. Assert:

- `document_id` is `{user_id}_{session_id}`.
- `llm_summary` is the space-joined `problem activity outcome`.
- The instruction-leak turn is excluded from `posts`; all other turns are present in order.
- Output JSON files have the exact `{document_id: str}` / `{document_id: [str]}` shapes.
- A session missing its summary or conversation file is skipped with a warning, not a crash.
- `--limit`/`--seed` produce a deterministic, reproducibly-sampled subset.

## Out of scope

- Writing `bundle_specs/therapeutic_sessions.yaml` or running `generate_bundle.py` against it —
  blocked on that generator being finished; this design only covers getting the dataset into the
  shape the generated bundle's CLI will expect.
- The `patient_summary.json` (cross-session) files — not used by this conversion.
- Any change to `generate_bundle.py`, `metric_registry.py`, or the metric classes themselves.
